# TaskFlow

Веб-приложение для управления задачами: создание задач, распределение между участниками команды и отслеживание прогресса выполнения.

## Структура проекта

```
TaskFlow/
├── backend/
│   ├── auth/        # регистрация, вход
│   ├── config/      # настройки и подключение к БД
│   └── tasks/       # логика задач
├── database/
│   └── schema.sql   # структура базы данных
├── frontend/        # внешка сайта 
│   ├── css/
│   ├── js/
│   └── pages/
├── index.php
└── README.md
```

## Первый запуск (один раз)

1. Склонируйте репозиторий в папку OSPanel:
   ```bash
   cd B:\OSPanel\home
   git clone <ссылка-на-репозиторий>
   cd TaskFlow
   ```
2. Создайте свой конфиг из шаблона:
   ```bash
   copy backend\config\config.example.php backend\config\config.php
   ```
   Откройте `config.php` и впишите свои данные для БД. Этот файл **не попадает в git**, и пароли никто не увидит.
3. Создайте базу данных:
   - откройте phpMyAdmin;
   - создайте базу `taskflow` (кодировка `utf8mb4_general_ci`);
   - откройте её, вкладка **Импорт**, выберите `database/schema.sql`, нажмите **Вперёд**.
4. Перезапустите OSPanel и откройте сайт в браузере.

## Правила работы с ветками

- У каждого участника **своя ветка**, она указана в таблице выше.
- **В `main` напрямую не коммитим.** Всё попадает в `main` только через Pull Request на GitHub.
- Перед каждым коммитом проверяем, на какой ветке находимся:
  ```bash
  git branch
  ```
  Текущая ветка отмечена звёздочкой `*`.
- Файл `database/schema.sql` меняет один человек. Остальных предупреждаем в чате.

## Как загрузить изменения ИЗ репозитория (получить чужую работу)

Делаем **каждый раз перед началом работы**:

```bash
git checkout main
git pull
git checkout feature/ваша-ветка
git merge main
```

Что происходит: обновляем `main`, возвращаемся в свою ветку и подтягиваем в неё свежие изменения команды.

Если в `database/schema.sql` что-то поменялось, заново импортируйте его в phpMyAdmin.

## Как загрузить изменения В репозиторий (отправить свою работу)

```bash
git status
git add .
git commit -m "feat: что именно сделал"
git push
```

Если ветка отправляется **в первый раз**, пишем так:

```bash
git push -u origin feature/ваша-ветка
```

Дальше достаточно просто `git push`.

После этого заходим на GitHub и создаём **Pull Request**: ветка `feature/ваша-ветка` в `main`. Кто-то из команды проверяет и нажимает **Merge**.


## Если что-то пошло не так

| Ошибка / ситуация | Что делать |
|-------------------|------------|
| `fatal: not a git repository` | Вы не в папке проекта. Перейдите: `cd B:\OSPanel\home\TaskFlow` |
| `There is no tracking information for the current branch` | Привязать ветку: `git push -u origin feature/ваша-ветка` |
| `CONFLICT` при `merge` или `pull` | Откройте файлы в VS Code, выберите нужный вариант (Accept Current / Incoming / Both), затем `git add .` и `git commit`. Отменить слияние: `git merge --abort` |
| Git ругается на несохранённые изменения | Закоммитьте их или уберите временно: `git stash`, затем `git pull`, затем `git stash pop` |
| Закоммитили не в ту ветку | Не пушьте. Напишите в чат команды, поможем перенести коммит |
| Не видно новой ветки коллеги | `git fetch origin`, затем `git checkout feature/название` |

## Шпаргалка

```bash
git status                 # что изменилось
git branch                 # на какой я ветке
git checkout имя_ветки     # переключиться на ветку
git checkout -b имя_ветки  # создать новую ветку и перейти на неё
git pull                   # забрать изменения с GitHub
git add .                  # добавить все изменения в коммит
git commit -m "сообщение"  # сохранить коммит
git push                   # отправить на GitHub
git log --oneline -5       # последние 5 коммитов
```

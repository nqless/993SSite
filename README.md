## 1. Общие сведения

Настоящий документ содержит описание функционального назначения, архитектуры, структуры данных и основных методов информационной системы «Поставка ИС Производства», разработанной в рамках экзаменационного задания по модулю 4. Основное назначение решения состоит в обеспечении авторизации пользователей, разделении прав доступа по ролям, контроле корректности входа с помощью интерактивной капчи-пазла, а также в администрировании учетных записей пользователей.

Документация оформлена в логической последовательности: сначала приводятся общие положения и назначение системы, затем описываются состав программного средства, структура базы данных, пользовательский интерфейс, алгоритмы работы и перечень используемых методов с указанием параметров.

## 2. Функциональное назначение

Информационная система предназначена для автоматизации доступа пользователей к функционалу программного комплекса. Система поддерживает две роли: «Администратор» и «Пользователь». Администратор имеет расширенные полномочия по управлению учетными записями, а пользователь получает доступ к рабочему окну с базовой информацией о своей учетной записи.

Форма авторизации обеспечивает обязательный ввод логина и пароля, проверку учетных данных по таблице «Пользователи», показ сообщений об ошибках и подтверждении успешного входа. Дополнительно на форме реализована интерактивная проверка «капча-пазл», в которой пользователь должен собрать исходное изображение из четырех фрагментов в правильном порядке.

При трех последовательных неудачных попытках входа, вызванных неправильным паролем или неправильной сборкой пазла, учетная запись блокируется. Повторная попытка входа в этом случае сопровождается сообщением о блокировке. Разблокировка учетной записи выполняется только пользователем с ролью администратора.

## 5. Описание базы данных

Для хранения учетных записей используется база данных Microsoft SQL Server. Поддерживается автоматическое создание базы данных при первом запуске приложения. Система подключается к серверу, проверяет наличие базы данных, при необходимости создает ее, затем создает таблицы и заполняет стартовыми данными.

Ключевой таблицей модуля 4 является таблица «Пользователи». В ней хранятся сведения, необходимые для аутентификации, авторизации, блокировки и сопровождения учетной записи.

**Таблица 2 — Состав таблицы «Пользователи»**

| Поле | Назначение | Пример значения | Примечание |
|---|---|---|---|
| UserId | Уникальный идентификатор пользователя. | 1 | Первичный ключ, identity. |
| FullName | Полное имя пользователя. | Иванов И.И. | Обязательное поле. |
| Login | Уникальный логин для входа. | admin | Не допускает дублирования. |
| PasswordHash | Хэш пароля пользователя. | PBKDF2 hash | В открытом виде пароль не хранится. |
| RoleName | Роль в системе. | Администратор | Допустимые значения: Администратор, Пользователь. |
| FailedAttempts | Количество последовательных неудачных попыток входа. | 2 | При достижении 3 учетная запись блокируется. |
| IsBlocked | Признак блокировки учетной записи. | 0 / 1 | 1 — пользователь заблокирован. |
| CreatedAt | Дата и время создания записи. | 2026-06-01 10:15:00 | Заполняется автоматически. |

При первом запуске приложения автоматически создаются стартовые учетные записи администратора и пользователя. Что позволяет сразу проверить работу формы входа, разграничение ролей и процедуры блокировки без ручного наполнения базы данных.

## 6. Описание пользовательского интерфейса

Основным экраном системы является форма авторизации. На ней располагаются поля ввода логина и пароля, кнопка входа, область капчи-пазла, а также служебные подсказки. Все элементы выравниваются по единой сетке, имеют логичную последовательность перехода по клавише ТАВ и масштабируются при изменении размеров окна.

После успешной авторизации под ролью администратора открывается рабочее окно с таблицей пользователей. В этом окне предусмотрены кнопки добавления нового пользователя, изменения существующего пользователя, снятия блокировки, поиска по логину или имени и обновления списка. Выбранная запись в таблице определяет контекст дальнейших административных действий.

После авторизации обычного пользователя открывается упрощенное рабочее окно, содержащее приветствие, логин, роль и кнопку завершения сеанса. Данное окно не содержит административных операций.

## 7. Описание алгоритмов и бизнес-логики

Алгоритм входа в систему включает последовательную проверку обязательности полей, состояния учетной записи, корректности капчи и корректности учетных данных. Сначала приложение контролирует, что поля «Логин» и «Пароль» заполнены. Далее по логину извлекается запись пользователя. Если запись отсутствует либо пароль не совпадает, увеличивается счетчик ошибочных попыток. После третьей ошибки учетная запись блокируется.

Проверка капчи выполняется до завершения процедуры аутентификации. Пользователь должен собрать изображение из четырех фрагментов. Сервис капчи хранит правильный порядок элементов и сравнивает его с текущим расположением фрагментов. Если порядок не совпадает, попытка считается неудачной и также влияет на счетчик ошибок.

Алгоритм работы администратора предусматривает загрузку списка пользователей из базы данных, фильтрацию списка по строке поиска, добавление пользователя с предварительной проверкой уникальности логина, редактирование имени, роли и пароля, а также снятие блокировки. При снятии блокировки одновременно сбрасывается счетчик неудачных попыток.

Для хранения паролей применяется хэширование. При создании пользователя или изменении пароля пароль преобразуется в криптографический хэш. При входе в систему введенное значение хэшируется аналогичным образом и сравнивается с сохраненным хэшом. Такой подход исключает хранение пароля в открытом виде.

**Таблица 3 — Основные бизнес-правила**

| Правило | Содержание |
|---|---|
| Обязательность полей | Поля логина и пароля не могут быть пустыми. |
| Проверка капчи | Пользователь допускается к входу только при правильно собранном пазле. |
| Блокировка | После трех последовательных ошибок входа учетная запись блокируется. |
| Разблокировка | Снятие блокировки выполняется только администратором. |
| Уникальность логина | При добавлении нового пользователя логин не должен повторяться. |
| Разделение ролей | Администратор и пользователь получают разные рабочие окна и наборы операций. |

## 9. Требования к надежности и обработке ошибок

Приложение должно корректно реагировать на ошибки пользовательского ввода, сетевые и инфраструктурные ошибки, а также на возможные исключения при работе с базой данных. Непредвиденная ошибка не должна приводить к аварийному завершению программы. Вместо этого пользователю выводится окно сообщения с кратким описанием проблемы и рекомендацией повторить действие либо обратиться к администратору.

Если логин или пароль не заполнены, пользователь получает информационное сообщение о необходимости ввода обязательных полей. Если учетная запись заблокирована, выводится сообщение о необходимости обращения к администратору. При нарушении требования уникальности логина администратор получает сообщение о том, что пользователь с таким логином уже существует.

При возникновении ошибок подключения к Microsoft SQL Server приложение должно информировать пользователя о невозможности подключиться к серверу, а также сохранять стабильность пользовательского интерфейса. Для служебной диагностики может использоваться файл журнала либо детальное сообщение в отладочном режиме.

## 10. Порядок развертывания и первичного запуска

Для запуска приложения требуется установленная среда выполнения .NET 8 и доступ к Microsoft SQL Server либо LocalDB. При первом запуске приложение считывает строку подключения из конфигурационного файла. Затем выполняется создание базы данных и таблиц, после чего в базу добавляются стартовые пользователи.

После первичного запуска рекомендуется выполнить проверку входа под учетной записью администратора, а затем под учетной записью обычного пользователя. Далее необходимо проверить срабатывание блокировки после трех последовательных ошибок и работу операции разблокировки из административного окна.

При использовании полноценного экземпляра Microsoft SQL Server вместо LocalDB в конфигурации приложения необходимо указать имя сервера, параметры аутентификации и флаги шифрования соединения. Подробный порядок переключения строки подключения приводится в эксплуатационной инструкции проекта.
